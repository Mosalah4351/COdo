<CRITICAL-DEFAULTS>

**Load `scrape:brief` before any crawling.** It turns the user's request into topics, schema contracts, and seed URLs. No crawl starts without a brief.

**Two questions before the crawl starts** (ask together, once, BEFORE any
fetching or planning fetches happen):
1. Does the user have an account on the platform? (Determines whether login-gated pages are in scope - if yes, follow `scrape:auth-session`: they log in manually once, you store the session.)
2. Should this run honour robots.txt? Ask directly - never assume. Record the answer in the run manifest before any request is made.

**Never fail silently, never fabricate.** Every requested datum ends in exactly one of three states: collected (with source URL + timestamp), empty (with the reason and the approaches tried), or blocked (with the blocking signal observed). A guessed value is worse than a missing one.

**Modern anti-bot systems layer their detection**: IP reputation, TLS/HTTP2 fingerprints, browser fingerprint (canvas/WebGL/fonts/navigator), and behavior patterns. Rotating user-agents alone accomplishes nothing. The countermeasures live in the skills: session warming, randomized behavior, hidden-element (honeypot) avoidance, and escalating browser tooling (vanilla Playwright -> Patchright). Respect them even when a page looks easy - you cannot see which detector is watching.

**CAPTCHA means stop, not solve.** A captcha is the site telling you your risk score crossed the line. Back off, cool down, report. Never solve captchas automatically unless the user has explicitly opted into a solving service.

**Speed comes from parallelism across topics, never aggression within one domain.** Many subagents on different domains/pages-in-flight yes; hammering one domain concurrently no.

</CRITICAL-DEFAULTS>

## The escalation ladder

Every URL climbs this ladder automatically; each failure logs WHY before climbing:

1. `scrape:static-fetch` - HTTP + parse with browser-realistic headers. Only works where no TLS-level bot detection exists; a challenge page means climb immediately.
2. `scrape:browser-render` - Playwright headless with session warming and human pacing.
3. `scrape:browser-render` hardened mode - Patchright (drop-in Playwright patch fixing CDP leaks) when vanilla gets flagged.
4. `scrape:api-discovery` - capture the site's own network traffic; find its internal JSON/GraphQL endpoints. Often cleaner than any HTML parsing, and APIs change less often than page layouts.
5. `scrape:auth-session` - authenticated pages (user consented first).
6. Blocked/exhausted - mark `blocked`, record signals seen (403/429/captcha/challenge page/empty), move on.

## The swarm

Decompose the brief into topics. Each topic becomes one subagent dispatch containing: the schema contract (exact JSON shape to return), seed URLs, the ladder, politeness caps, and its checkpoint path under `.codo/scrape/<run-id>/`. Subagents append rows to their checkpoints continuously - a killed machine never loses collected data. When all checkpoints settle, merge, dedupe by natural key, QA, then hand off to `business:xlsx-official` for the workbook: one sheet per topic plus a Sources sheet.

## Honesty contract

Three terminal states per datum, recorded in the output:
- `collected` - value + source_url + scraped_at
- `empty` - reason (e.g. "page has no such section") + attempts made
- `blocked` - signal observed (e.g. "429 after 3 attempts") + cooldown status

Report coverage at the end: X% collected, Y% empty, Z% blocked - and what would unlock the blocked portion (login, different rung, manual step).
